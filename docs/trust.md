# Модель доверия (черновик v1)

Цель: любая нода может **сама, без связи с control** проверить:
- что домен реально зарегистрирован в зоне;
- что регистратор реально допущен владельцем зоны;
- что зона реально выпущена control;
- что ничего из этого не отозвано и не снято (с оговоркой о свежести, §6).

Основа: сертификаты как в TLS + transparency-логи как в Certificate Transparency + пороговые ключи как в TUF.

## 1. Цепочка

```
Root key                   оффлайн, у тебя. Shamir 2-из-3: три копии-доли в разных местах
│                          (ноутбук в сейфе / бумага / второй город). Публичный ключ вшит в клиент.
│                          Используется: выпуск/ротация ключа control, отзыв control. Раз в год.
│
└─ Control key             ОДИН публичный ключ, но приватный разделён между 3 серверами
   │                       (FROST, порог 2-из-3). Подпись — обычная Ed25519, проверяющему
   │                       не важно, что её делали втроём. Упал 1 сервер — control работает.
   │
   ├─ Zone cert            ".brand" → ключ владельца зоны, срок, правила зоны
   │  │
   │  ├─ Registrar cert    ключ регистратора, выдаёт ВЛАДЕЛЕЦ ЗОНЫ (не control)
   │  │
   │  └─ Domain record     "shop.brand" → ключ владельца домена, срок
   │     │                 подписан регистратором, попадает в лог зоны
   │     └─ DNS-записи     подписаны ВЛАДЕЛЬЦЕМ ДОМЕНА:
   │                         host    → NodeID(ы) хоста
   │                         txt     → что угодно
   │
   ├─ Override             «домен X снят/заморожен с момента T, причина» — takedown (§5)
   └─ Revocation           «зона/ключ X отозван с момента T»
```

Relay, Exit, Host — **без сертификатов** (permissionless). Их идентичность — просто NodeID. Доверие к exit — репутация и мелкие платежи, а не допуск от control.

Ключевая деталь: **владелец домена сам подписывает DNS-записи**. Регистратор, владелец зоны и control не могут тихо перенаправить домен. Отобрать могут (control через override), но это будет записано в логе.

## 2. Зоны и несколько регистраторов в одной зоне

- Control выпускает зону заявителю (платно, в RIFT) → заявитель становится **владельцем зоны** с полным контролем: цены, правила имён, допуск регистраторов.
- В зоне может быть **много регистраторов** (Q-T3 = B). Владелец зоны выдаёт им сертификаты.
- **Конфликт «два регистратора продали одно имя»** решается логом зоны: его ведёт владелец зоны, он и есть секвенсор. Регистратор отправляет заявку → владелец зоны добавляет в лог, если имя свободно → первый в логе — владелец. Регистратор отдаёт клиенту домен только с доказательством включения в лог.
- Следствие: **владелец зоны оффлайн → регистрация в его зоне стоит**. Существующие домены работают. Принято для v1.

## 3. Transparency-логи

Логи ведут: control (зоны, overrides, отзывы) и каждый владелец зоны (регистраторы, домены).

- Лог публикует подписанную «голову» (Signed Tree Head: размер, корень Merkle, время).
- К каждой записи прикладывается inclusion proof.
- Witness-ноды зеркалят логи и подписывают головы. Голова валидна, если её подписали ≥ K witness'ов → control или владелец зоны не может показать разным нодам разную историю.
- **Пока root только у тебя, witness'ы — единственное, что делает control подотчётным.** Поэтому witness должен быть доступен любому желающему с первого дня.

Валидная запись = подписи по цепочке ✔ + inclusion proof ✔ + голова подписана witness'ами ✔ + не отозвана / не снята ✔ + не истекла ✔.

## 4. Время и «смерть» родителя

**Валидность ребёнка проверяется на момент выпуска**, а время выпуска — время головы лога, куда попала запись. → Истёк сертификат родителя или родитель умер — дети живут до своего срока.

**Как это сделано в коде (`rift-trust`):**
- Сертификат ребёнка должен быть *выпущен* в окне действия родителя (`issued_at` ∈ [родитель.issued_at, родитель.expires_at]). Так control, умерший или просроченный *после* выдачи зоны, ничего не ломает.
- Срок самого **control** — только окно выпуска; «сейчас» он не проверяется (его ротация раз в 90 дней не должна убивать все домены).
- Зона, регистратор, домен и записи проверяются «сейчас»: домен не живёт дольше зоны.
- Пока нет лога, `issued_at` подписывает сам выпускающий — задним числом поймать нельзя. Закрывается transparency-логом (§3), это следующий шаг.

## 5. Takedown (Q-T5 = да)

- Control публикует в своём логе `Override(domain, action=freeze|seize, reason, T)`.
- Клиенты проверяют overrides control поверх записей зоны: override control сильнее записи зоны.
- `seize` может передать домен другому ключу. `freeze` — просто не резолвится, с показом причины пользователю.
- Все overrides публичны и навсегда в логе. Злоупотребление видно всем.
- Жалобы подаются на `rift://control.rift` (architecture.md §6.5), подписаны ключом заявителя. Решает control, решение публикуется в логе вместе с причиной.

## 5a. Выдача зон

- Имена зон — любые. Заявка подаётся на `rift://control.rift`, оплата в RIFT + стейк.
- Автоматических отказов нет: каждую заявку вручную рассматривает основатель. Совпадения с реальными TLD (`.com`, `.ru`) — повод присмотреться (фишинг), но решение за человеком.
- Control может **отклонить** заявку или **передать** уже выданную зону другому владельцу (запись `ZoneTransfer` в логе control, старый zone cert отзывается). Существующие домены зоны переезжают вместе с ней: новый владелец получает лог зоны и продолжает его.
- Зона `.rift` — системная, у control.

## 5b. Резолверы и объявления (как в коде)

- **Резолвер — недоверенный кэш.** Хост публикует свою цепочку (`Bundle`) любому числу резолверов, клиент спрашивает их и проверяет цепочку сам по root. Резолвер может только промолчать или отдать устаревшее — поэтому клиент берёт самую свежую (`seq`) из ответов нескольких резолверов. Резолвер не принимает на хранение то, что не проходит проверку.
- **Объявление (`Announcement`) несёт свой control-сертификат**, который проверяется по root. Иначе takedown от control нового поколения (ротация каждые 90 дней) не действовал бы на домены из цепочки старого. `None` вместо сертификата — подписал сам root (отзыв control).
- **Замороженный или отозванный домен — отказ, если это подтвердил хотя бы один резолвер**: безопаснее не открыть сайт, чем открыть замороженный.
- Видят объявление только те резолверы, которым его опубликовали; нужен канал рассылки (gossip) и лог. Пока — `riftd publish --notice`.

## 6. Отказы

| Событие | Что работает | Что не работает |
|---|---|---|
| 1 из 3 control-серверов упал | Всё | — |
| 2–3 control-сервера упали | Связность, VPN, резолв, сайты, регистрация доменов в существующих зонах | Новые зоны, takedown, отзывы |
| Владелец зоны оффлайн | Домены зоны | Новые домены и продления в этой зоне |
| Регистратор оффлайн | Всё; другие регистраторы зоны продают | Продажи этого регистратора |
| Доля control-ключа украдена (1 сервер взломан) | Одной доли мало. Перевыпуск долей (FROST refresh) | — |
| 2 доли украдены | Root отзывает control key, выпускает новый. Всё, что подписано украденным, видно в логах | — |
| Владелец зоны продаёт чужие домены / сошёл с ума | Видно в логе зоны. Control отзывает зону или переводит её новому владельцу | — |
| Root-доля потеряна | Остальные 2 восстанавливают | — |
| 2 root-доли потеряны | Всё работает до истечения сроков | Сеть «замерзает». Храни доли в разных местах |
| Тебя / серверы захватили | Логи и witness'ы делают захват **видимым**, но не невозможным. Плата за «полу-независимость» | — |

## 7. Отзыв и свежесть

- Отзывы и overrides — записи в логе control, разносятся gossip'ом через relay и DHT.
- Клиент знает, насколько свежа его голова лога: старше 24 ч — мягкое предупреждение, старше 7 дней — жёсткое. Числа подстраиваем.
- Сроки: зоны — 1–2 года, домены — 1 год, регистраторы — на усмотрение владельца зоны.
