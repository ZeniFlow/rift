# Браузер Rift (фаза 4)

Приложение `rift-app` (Tauri 2): окно с панелью (адрес, назад/вперёд/обновить, значок проверки) и страницей сайта.
Сети в окне нет — всё идёт через `librift`: имя → проверенная цепочка → хост → HTTP по QUIC.

## Как сайт попадает в WebView

Проверено в WKWebView (macOS, Tauri 2) на реальной странице, четыре варианта адреса:

| адрес страницы | secure context | cookie | Service Worker | origin |
|---|---|---|---|---|
| `rift://shop.brand/` (кастомная схема) | да | **нет** | **нет** | свой на сайт |
| `http://shop.brand.<метка>.localhost:порт/` | да | да | да | свой на сайт |
| `http://127.0.0.1:порт/`, `http://localhost:порт/` | да | да | да | один на порт |

**Вывод:** кастомная схема `rift://` даёт `crypto.subtle`, `randomUUID`, буфер обмена, но cookie не сохраняются и
Service Worker не регистрируется, то есть Node-приложения с cookie-сессиями на ней не заработают. А `*.localhost`
считается безопасным контекстом без TLS, поэтому **локальный CA и `https://*.rift` не нужны**. Сайты открываются
через локальный шлюз (`librift::gateway`), а в адресной строке остаётся `rift://имя.зона/путь`.

### Защита шлюза

Шлюз слушает loopback, но виден любой программе на машине (в том числе странице в другом браузере).
Поэтому в адресе сайта стоит секретная метка: `метка = HMAC(секрет установки, имя)`:
- чужая страница не знает метки: DNS-rebinding и запросы «от лица пользователя» дают 403;
- метка своя у каждого сайта, значит сайты друг для друга cross-site, и SameSite-cookie работают как в обычном вебе;
- метка постоянна для установки (секрет лежит в `<каталог данных>/gateway-secret`), поэтому localStorage сайтов
  переживает перезапуск; порт шлюза тоже постоянный (`47878`).

### Что шлюз делает с запросом и ответом

- `Host` = имя сайта, `Origin`/`Referer` = `https://имя`, `X-Forwarded-Proto: https` (проверки CSRF в Django/Next и подобных видят то, что ждут);
- в `Set-Cookie` убирается `Domain` (иначе браузер отверг бы cookie на адресе шлюза);
- абсолютные `Location` на собственное имя возвращаются на адрес шлюза;
- из ответа убираются `Strict-Transport-Security` и `upgrade-insecure-requests` в CSP (на http-адресе шлюза они всё сломали бы);
- `Upgrade` (WebSocket) проходит через шлюз, клиента и хост до приложения.

Не делает: тела ответов не переписываются, абсолютные ссылки `https://имя/…` внутри HTML остаются как есть.

## Рамка окна и дизайн

Панель занимает место заголовка, как в Chrome: одна чёрная полоса с навигацией, адресом и кнопками окна.

| платформа | рамка | кнопки окна | проверено |
|---|---|---|---|
| macOS | прозрачный заголовок (`Overlay`), содержимое под ним | родные; приложение переносит их на середину панели | да: нативные рамки видов и кнопок измеряются в `selftest-ui` |
| Windows | без системной рамки (`decorations(false)`) | рисует панель (свернуть, развернуть/восстановить, закрыть); границы и тень окна обрабатывает Tauri | нет: только вид панели в браузерном движке |
| Linux | системная | системные | нет |

Почему Linux остаётся с системной рамкой: у безрамочного окна GTK нет границ для изменения размера, а Tauri их там не добавляет;
свои потребовали бы отдельных видов по краям окна. На Windows 11 у своих кнопок нет всплывающих раскладок Snap Layouts.

Дизайн: только тёмная тема, фон `#000`, один акцентный цвет без градиентов; интерактивное скруглено полностью
(круглые кнопки, адресная строка и чипы в форме капсулы), крупные поверхности — радиусами 10–14 px; иконки — только SVG
(без эмодзи и символов-иконок); анимации короткие (120–220 мс) и отключаются при `prefers-reduced-motion`; раскладка
адаптивна по ширине (на узких окнах подпись чипа сворачивается в иконку, затем пропадают «вперёд» и «обновить»).
Те же токены используют страницы ошибок шлюза и стартовая страница (`librift::pages`).

Раскладка двух видов проверяется по **настоящим** нативным рамкам (`rift-app/src/native.rs`), а не по тому, что сообщает Tauri:
на macOS он считает границы той же формулой, которой их задаёт, и перекрытие панели страницей не замечает.

## Вкладки, история, закладки

Окно состоит из панели `ui` (строка вкладок высотой 36 px с кнопками окна и под ней строка адреса, 44 px) и WebView на каждую вкладку
(`tab-<id>`, виден один, остальные скрыты, но живут). Новая вкладка открывает `browser://newtab`: закладки и часто открываемые сайты.
`target=_blank` и `window.open` открываются во вкладке. Закрытие последней вкладки закрывает окно.

Новый WebView в окне ложится поверх всех, в том числе поверх слоя `overlay`, поэтому после создания вкладки слой переносится наверх
(`Webview::reparent`). Самопроверка на macOS сверяет это по настоящему порядку видов и по тому, что неактивные вкладки скрыты.

- **История** (`history.json`): адрес как его видит пользователь (`rift://имя.зона/путь`, а не адрес шлюза), заголовок, время. Один и тот же
  адрес подряд в пределах 30 с это одна запись, всего помним 5000. Не пишутся: страницы `browser://`, пустая вкладка, сайты Rift, чьё имя
  не проверилось, и всё при выключенной настройке «Сохранять историю». Страница `browser://history`: поиск, удаление записи, очистка с подтверждением.
- **Закладки** (`bookmarks.json`): звёздочка в адресной строке ставит и снимает закладку на открытую страницу; `browser://bookmarks`: список, поиск, удаление.
- Файлы лежат только на этом устройстве. Повреждённый файл откладывается в `*.bad`, а не затирается.
- **Подсказки** под адресной строкой: закладки, затем история (адреса, начинающиеся с запроса, выше; дальше чаще и свежее открывавшиеся). Стрелки выбирают,
  Enter открывает выбранное, Escape закрывает. Список рисует слой `overlay` (его WebView на это время по размеру списка), фокус остаётся в адресной строке.
  Уведомление, висевшее в этот момент, убирается: слой один. Меню и окна важнее подсказок.
- **Фон.** Окно и WebView своих страниц чёрные с первого кадра, чтобы новая вкладка не мигала белым. Чужие сайты получают обычный белый фон.
- **Сочетания клавиш.** macOS: меню приложения (⌘T, ⌘W, ⌘L, ⌘R, ⌘D, ⌘Y, ⌘,, ⌘[ и ⌘]) работает и тогда, когда фокус в странице сайта.
  Windows и Linux: сочетания (Ctrl+T, W, L, R, D, H, `,` и Alt+стрелки) работают, пока фокус в панели; из страницы сайта их пока не перехватить.

## Слой, компоненты и настройки

Третий WebView `overlay` (прозрачный, поверх всего, скрыт, пока пусто) рисует переиспользуемые компоненты из `ui/kit.js` + `ui/kit.css`:
выпадающая плашка (`popover`, у значка проверки), меню, модальное окно, `alert` / `confirm` / `prompt`, уведомления.
Все они анимируются (вход/выход, каскад пунктов меню), закрываются по Escape, держат фокус (в модальных Tab не выходит наружу).
Сведения о сайте и меню `⋮` открываются через `overlay_open`; диалоги с ответом — через `overlay_ask` (страница ждёт результат).

Размытие под плашкой и окном — системное (`NSVisualEffectView`, только macOS); на остальных системах поверхности непрозрачные.
Прозрачный WebView на macOS требует `macOSPrivateApi` (в App Store с этим флагом приложение не примут).
Увидеть размытие может только человек: автоматика не снимает экран, она проверяет, что вид размытия лежит ровно под плашкой и убирается.

**`browser://settings`** — страница настроек как `chrome://settings`: открывается в окне страницы (`ui/settings.html`), без значка проверки,
с боковым разделом и поиском. Настройки (`settings.json` в каталоге данных): акцент, сохранение истории, размытие (выкл/мягкое/сильное), затемнение за окнами,
анимации (системные/полные/сниженные/выкл), «сначала искать в Rift». Применяются сразу во всех видах (событие `settings`), значения
проверяются при записи. Сбросить можно с подтверждением. `Cmd/Ctrl + ,` и пункт меню открывают страницу. Зона `browser` зарезервирована
за приложением. Новую настройку добавляют строкой в `GROUPS` страницы и ключом в `settings.rs`.

## Безопасность окна

- Страница сайта — **чужой код**: в `content`-WebView нет доступа к командам приложения. Права выданы панели, слою и
  странице настроек (`capabilities/default.json`, только локальные адреса: `remote` не выдан). Из страницы сайта нельзя перейти на другие
  файлы приложения, кроме `settings.html`. Самопроверка: вызов `navigate` со страницы сайта даёт отказ.
- Панель показывает значок результата проверки цепочки по root: «проверен» (владелец, число хостов, версия записей),
  «заморожен», «не проверен».
- Адрес без схемы — сначала Rift (P7); если имени в сети нет — обычный `https://`.

## Запуск

```bash
cargo run -p rift-app -- demo           # окно браузера + сайт в сети Rift, поднятой в процессе
cargo run -p rift-app -- selftest       # WebView открывает сайт: cookie, Service Worker, WebSocket, редиректы, secure context
cargo run -p rift-app -- selftest-ui    # то же через панель: ввод адреса, назад/вперёд, статус, заморозка
cargo run -p rift-app -- pages <папка>  # выгрузить стартовую страницу и страницы ошибок, чтобы посмотреть вёрстку
cargo run -p rift-app                   # настоящий браузер; сеть и доверие — из <каталог данных>/config.json
```

`<каталог данных>` — `~/.rift-app` или `$RIFT_APP_HOME`. Пример `config.json`:

```json
{
  "root": "<публичный ключ root, 64 hex>",
  "witnesses": ["<публичный ключ свидетеля>", "<…>"],
  "threshold": 2,
  "resolvers": ["<NodeID>@https://relay.example.com"],
  "relay": "https://relay.example.com"
}
```

Приложение не входит в `default-members` workspace: оно тянет Tauri и системные библиотеки WebView, поэтому обычный
`cargo build` / `cargo test` не собирают его (`cargo build -p rift-app`); в CI он собирается отдельным заданием на трёх системах.

## Что ещё нет

- Панель закладок под строкой адреса, перетаскивание и закрепление вкладок, значки сайтов (favicon).
- Сочетания клавиш из страницы сайта на Windows и Linux.
- VPN и кошелёк в окне (ядро VPN есть в `librift::vpn`, но TUN требует прав; кошелёк — фаза 5).
- Поиск по сети, диалог «заявка на зону» (`control.rift`).
- Установочные пакеты и подпись приложения (`cargo tauri build`), Windows/Linux/Android/iOS (сам Tauri 2 их умеет, проверок не было).
- Скриншотов окна автоматика не делает (macOS не даёт запись экрана процессу); вид панели проверен в браузерном движке,
  а поведение — самопроверкой `selftest-ui`.
